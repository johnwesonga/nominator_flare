# Phase 2: Worker project

Status: **complete**

This phase adds a Cloudflare Worker project beside the existing Gleam frontend.
It establishes the runtime, routing, static asset, environment, test, and build
boundaries without implementing database behavior. D1 schema work remains in
Phase 3, and the routes deliberately return `501 Not Implemented` until their
implementation phases.

## Platform decisions

- Wrangler JSONC is the configuration source of truth.
- The compatibility date is `2026-08-14`, the date this Worker was created.
- The Worker uses ES modules and generated binding/runtime types.
- `nodejs_compat` is enabled for library compatibility.
- Workers Static Assets serves `dist/`.
- SPA fallback uses `not_found_handling: "single-page-application"`.
- `run_worker_first: ["/api/*"]` ensures API paths execute Worker code instead
  of falling through to `index.html`.
- Development, preview, and production have separate D1 and Queue binding
  configurations.
- Persisted Workers Logs are enabled with a full initial sampling rate. This can
  be reduced after real traffic characteristics are known.

These choices follow the current [Wrangler configuration](https://developers.cloudflare.com/workers/wrangler/configuration/),
[Static Assets SPA routing](https://developers.cloudflare.com/workers/static-assets/routing/single-page-application/),
and [Workers Vitest integration](https://developers.cloudflare.com/workers/testing/vitest-integration/)
documentation.

## Files changed

### `.gitignore`

Added `dist/` and `node_modules/`. The production bundle is generated and npm
dependencies are restored from lockfiles; neither belongs in version control.

### `package.json` and `package-lock.json`

Added a private npm project and locked the Worker toolchain:

- Wrangler;
- TypeScript and Node.js types;
- Vitest; and
- Cloudflare's Workers Vitest pool.

Scripts now provide:

| Script | Purpose |
|---|---|
| `npm run build:frontend` | Build the minified Lustre bundle and copy CSS into `dist/` |
| `npm run dev` | Serve the Worker, local bindings, and static assets |
| `npm run types` | Regenerate types from Wrangler configuration |
| `npm run types:check` | Verify generated types have not drifted |
| `npm run typecheck` | Type-check Worker and test TypeScript |
| `npm test` | Run tests inside the Workers runtime |
| `npm run deploy:dry-run` | Bundle and validate without deploying |
| `npm run check` | Run the frontend build and every Worker verification above |

Wrangler disk logging is disabled for CLI scripts with
`WRANGLER_WRITE_LOGS=false`; application observability remains enabled. This
keeps local CLI state inside the project boundary and does not disable deployed
Worker logs.

### `wrangler.jsonc`

Added:

- Worker name and TypeScript entry point;
- current compatibility date and `nodejs_compat`;
- Static Assets binding, SPA fallback, and Worker-first API routing;
- `DB` D1 binding;
- `EMAIL_QUEUE` producer plus consumer and dead-letter queue settings;
- non-sensitive origin, environment, and sender-name variables;
- observability; and
- isolated `preview` and `production` bindings.

The D1 and Queue declarations use Wrangler automatic provisioning and therefore
do not contain resource IDs or secrets. No remote resources were provisioned in
this phase.

The preview and production hostnames use `example.com` placeholders. They must
be replaced with the real hostnames before the first remote deployment.

### `worker-configuration.d.ts`

Generated by `wrangler types`. It is the source of the `Env`, runtime,
`D1Database`, `Queue`, `Fetcher`, and `ExportedHandler` types. Binding interfaces
are not maintained by hand.

### `tsconfig.json`

Added strict TypeScript checking for Worker code, tests, configuration, and the
generated Wrangler declaration. No JavaScript output is emitted by TypeScript;
Wrangler owns bundling.

### `vitest.config.ts`

Configured Cloudflare's Vitest plugin to load `wrangler.jsonc` and execute tests
inside the Workers runtime rather than Node's browser approximation.

### `worker/src/index.ts`

Added the ES-module Worker entry point. It:

- awaits route handling;
- converts unexpected failures into the frozen error envelope;
- logs only a structured event and error class, never request data; and
- exposes a Queue consumer stub that fails messages until Phase 8 implements
  delivery, ensuring messages are not falsely acknowledged.

### `worker/src/router.ts`

Added exact method/path recognition for all nine endpoints frozen in Phase 1.
Known paths with the wrong method return `405` with `Allow`; unknown API paths
return `404`.

### `worker/src/responses.ts`

Added the shared JSON error envelope, `Cache-Control: no-store`, request IDs,
and a Phase 2 `501` response helper.

### `worker/src/routes/`

Added separate ballot, vote, admin, and notification route modules. They return
`501` until the matching migration phase supplies behavior. Returning an
explicit error prevents mock data from being mistaken for production state.

### `worker/test/router.test.ts`

Added 11 Worker-runtime tests covering every frozen route, the standard `501`
envelope, unknown-route `404`, and method-mismatch `405` behavior.

### Frontend output

The Lustre build produces these ignored artifacts:

```text
dist/
  index.html
  nominator_flare.js
  styles.css
```

The existing Supabase transport remains in the bundle until Phase 6. Phase 2
changes hosting and API scaffolding only.

### `README.md`

Replaced the generic package instructions with local Worker setup, frontend
build, verification commands, and a link to migration documentation.

## Environment binding map

| Environment | Worker | D1 | Queue | Dead-letter queue |
|---|---|---|---|---|
| development | `nominator-flare` | `nominator-development` | `nominator-email-development` | `nominator-email-development-dlq` |
| preview | `nominator-flare-preview` | `nominator-preview` | `nominator-email-preview` | `nominator-email-preview-dlq` |
| production | `nominator-flare-production` | `nominator-production` | `nominator-email-production` | `nominator-email-production-dlq` |

Bindings are non-inheritable in Wrangler, so D1, Queue, and non-sensitive
variables are repeated explicitly for named environments.
